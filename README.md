# Otbor

Программа для отбора картинок, сделанных набором FluxKit. Показывает варианты каждого задания, раскладывает файлы
на нужные и ненужные, а результат сама отправляет сюда, в `status/status.json`: что готово и что надо переделать.
Картинки в репозиторий не попадают.

Репозиторий публичный: здесь видны имена и подписи заданий и комментарии к ним, поэтому ничего личного в комментариях
писать не стоит. Ключа доступа здесь нет и быть не должно.

## Установка на ПК с генерацией

В папке FluxKit откройте терминал (правый клик по пустому месту папки, «Открыть в терминале») и выполните по очереди:

```bat
curl.exe -fsSLo UPDATE.bat https://raw.githubusercontent.com/levkastergit/otbor/main/kit/UPDATE.bat
.\UPDATE.bat
```

`UPDATE.bat` кладёт `Otbor.exe` в `results`, обновляет копию в корне FluxKit, если она там есть, обновляет скрипты
в `scripts` и добавляет `5_REGEN.bat`. Перед запуском закройте `Otbor.exe`. Дальше обновления ставятся кнопкой в пульте.

Готовая программа отдельным файлом лежит на странице [Releases](https://github.com/levkastergit/otbor/releases/latest).

## Работа

1. Запустите `results\Otbor.exe` или копию в корне FluxKit: обе открывают папку `results`. При первом запуске
   программа попросит ключ GitHub: кнопка откроет страницу создания
   ключа с заполненными полями, останется выбрать репозиторий `otbor`, нажать Generate token и вставить ключ в окно.
   Срок ключа 90 дней, по истечении программа попросит новый. Без ключа отбор работает, данные уйдут после подключения.
2. Разбирайте задания. Панель слева показывает, сколько разобрано; клик по строке переходит к ней. Зелёная строка
   в шапке говорит, куда идёт картинка: уровень, сцена и список поиска. Порядок очереди меняют кнопки над панелью, выбор
   запоминается:

   - **Разделы:** сначала персонажи, каждый целиком (позы, затем портреты), потом локации (фон, декор, предметы),
     мини-игры, интерфейс и сюжетный реквизит.
   - **Уровни:** как в игре, от пролога до финала. Внутри уровня персонажи, затем сцены по порядку и мини-игра. Задание
     стоит там, где встречается первым, остальные места показаны в зелёной строке.


   | Действие | Мышь | Клавиша |
   |---|---|---|
   | Отметить вариант, можно несколько | клик | цифра |
   | Подтвердить и перейти дальше | «Далее» | Enter или пробел |
   | Выбрать вариант и сразу перейти дальше | двойной клик | |
   | Посмотреть крупно | правый клик | внутри: ←/→ и Esc |
   | Ни один не подходит, на перегенерацию | кнопка | 0, затем Enter |
   | Вернуть предыдущее задание | «Назад» | Backspace |
   | Отложить в конец раздела | «Пропустить» | S |
   | Перейти к персонажу, локации или сцене | клик в панели слева | |
   | Переключить разделы и уровни | кнопки над панелью | L |
   | Посмотреть выбранное в разделе | «Выбранное» или клик по разобранному разделу | V |
   | Открыть пульт: генерация, обучение, обновление | «Пульт» | G |
   | Вырезанные или как есть | кнопка | A |

3. Сравнивайте выбранное. Обзор показывает весь выбор раздела рядом, по плитке на вариант, и работает после перезапуска:

   | Действие | Мышь | Клавиша |
   |---|---|---|
   | Отметить для сравнения | клик | цифра |
   | Сравнить отмеченные крупно, от двух штук | «Сравнить отмеченные» | Enter |
   | Посмотреть крупно | правый клик | внутри: ←/→ и Esc |
   | Переделать выбор отмеченного задания | «Выбрать заново» | R |
   | Другая страница, если выбрано больше 12 | кнопки страниц | ←/→ |
   | Вырезанные или как есть | кнопка | A |
   | Выйти | «Назад» | Esc |

   «Выбрать заново» открывает задание со всеми вариантами, а после выбора возвращает в обзор. Вырезанные картинки
   подогнаны под плитку; чтобы сравнить фигуры на целом холсте, нажмите A.
4. Кнопка GitHub внизу показывает состояние отправки. Отправка идёт сама через 10 секунд после последнего решения и не
   чаще раза в 30 секунд; нажатие на кнопку отправляет сразу. При закрытии окна неотправленное уходит сразу. Если связи
   нет, данные остаются на ПК и уйдут позже.
5. Когда появится ответ, что задания поправлены, нажмите в пульте «Перегенерировать отмеченные». Новые варианты сами
   появятся в очереди.

## Пульт

Окно запускает всё, что раньше делали отдельные bat-файлы, и показывает ход работы. Пока идёт задача, можно разбирать
картинки дальше: новые варианты попадут в очередь, когда она закончится.

| Кнопка | Что делает |
|---|---|
| Обновить программу | Ставит последний релиз: `Otbor.exe` и файлы из `kit/files.txt` одного тега, затем перезапускает программу |
| Перегенерировать отмеченные | Только задания, отмеченные «Ни один не подходит» |
| Сгенерировать несделанное | Все задания, которых ещё нет; готовые и разобранные пропускаются |
| Пробы стиля | Четыре проверочных задания |
| Обучить модели | Учит только те модели, которых ещё нет |
| Дообучить персонажей | Новая модель `pd_char_v2`, см. ниже |
| Открыть сравнение моделей | Лист: первая строка прежняя модель, ниже последние чекпойнты новой, промпты и seed те же |
| Генерировать дообученной моделью | Галочка: генерация и перегенерация берут `pd_char_v2` |
| Установить окружение | То же, что `1_INSTALL.bat`, готовые шаги пропускаются |
| Подключить Google Диск | Указать папку приложения Google Диск, см. ниже |
| Выложить сейчас | Не ждать автоматической выкладки |

Журналы задач лежат в `results\logs`. Bat-файлы остались запасным вариантом.

## Google Диск

Готовые картинки сами попадают на Google Диск через официальное приложение
[Google Drive для компьютера](https://dl.google.com/drive-file-stream/GoogleDriveSetup.exe). Программа кладёт файлы в его
папку, в облако их выгружает приложение, поэтому у программы нет ни пароля, ни ключа Google.

1. Установите приложение и войдите в нужный аккаунт. В нём можно держать
   [до четырёх аккаунтов](https://support.google.com/drive/answer/10838124?hl=en).
2. В пульте нажмите «Подключить Google Диск» и укажите «Мой диск» этого аккаунта.

В `Мой диск\Папины дочки спрайты` появляются папки разделов, например `Персонажи\Даша`. Выкладываются вырезанные спрайты,
а фоны и другие картинки без вырезанной версии — как есть. Выкладка идёт через 5 секунд после решения. Если выбор отменён
кнопками «Назад» или «Выбрать заново», картинка убирается и с Диска. Удаляются только файлы, которые выложила сама
программа, их список лежит в `results\_диск.json`. Если приложение закрыто, выкладка повторяется раз в минуту.

## Дообучение

Новая модель учится заново на `datasets\char_v2`: все исходные образцы плюс отобранные картинки. Прежняя модель не
меняется, на ПК 3 это около 65 минут: 3000 шагов при 1,28 с на шаг из лога обучения. `retrain.py` берёт отобранное так:

- у персонажа не больше картинок, чем исходных образцов, но до четырёх всегда можно;
- не больше двух вариантов на задание, сначала по одному с каждого;
- задания со словом `invisible` пропускаются: модель могла дорисовать мебель, а подпись
  [должна описывать всё видимое](https://docs.bfl.ai/flux_2/flux2_klein_training);
- картинки самой `pd_char_v2` не берутся: при многократном дообучении на собственных картинках
  [качество моделей падало](https://arxiv.org/abs/2311.12202), и отбор лучших от этого не защищал.

Дообучение стоит запускать один раз, когда разобран раздел персонажей.

## Что куда попадает

| Где | Что |
|---|---|
| `results\_Нужные\<группа>\<задание>` | выбранные варианты с вырезанными копиями |
| `results\_Ненужные\<группа>\<задание>` | остальные варианты, программа ничего не удаляет |
| `results\выбор.csv` | что выбрано для каждого задания: раздел, уровень, куда идёт, ассет |
| `results\_вид.txt` | какой порядок очереди выбран |
| `results\_диск.json` | что уже выложено на Google Диск |
| `results\перегенерировать.txt` | задания без подходящего варианта и комментарии |
| `results\_отбор.json` | журнал для кнопки «Назад» и продолжения работы, удалять нельзя |
| `results\_статус.json` | то же, что отправляется на GitHub |
| `status/status.json` в этом репозитории | итог с этого и других ПК |

Ключ лежит в `%LOCALAPPDATA%\Otbor\github.key` и расшифровывается только тем пользователем Windows, который его ввёл.

## Формат status/status.json

```json
{
 "summary": {"ready": 1, "regen": 1, "left": 683},
 "jobs": [
  {"id": "char_papa_stand", "group": "10_char", "ru": "Папа стоит", "state": "ready",
   "picked": ["char_papa_stand__ref_3"], "tried": ["char_papa_stand__ref_1", "..."],
   "note": null, "at": "2026-11-01 12:00:00", "pc": "a1b2c3d4"},
  {"id": "port_dasha", "group": "20_port", "ru": "Даша", "state": "regen",
   "picked": [], "tried": ["port_dasha__ref_1", "..."],
   "note": "лицо не похоже", "at": "2026-11-01 12:01:00", "pc": "a1b2c3d4"}
 ]
}
```

- `state`: `ready` — вариант выбран, заново не генерировать; `regen` — ни один не подошёл.
- `tried`: все показанные варианты задания. Новые номера и seed идут после них.
- `note`: что не понравилось, необязательно.
- `pc`: первые 8 символов SHA-256 от имени компьютера. Записи других ПК программа не трогает, при расхождении верна
  более свежая. Своя запись убирается кнопкой «Назад».

На файл задания идёт одна строка, поэтому изменения удобно смотреть в истории репозитория.

## Перегенерация

Кнопка пульта и `5_REGEN.bat` (`generate.py --regen`) берут `status/status.json` и `regen/overrides.json` с GitHub, а также
`results\_статус.json`, и делает только задания `regen`. Обычный `3_GENERATE.bat` готовые задания пропускает.

`regen/overrides.json` — правки заданий перед перегенерацией: id задания и поля из `jobs.json`, которые надо заменить.
В `refs` можно указать отобранную картинку, путь отсчитывается от папки FluxKit. Так новая поза получает ту же кровать
или одежду. FLUX.2 klein принимает [до четырёх образцов](https://docs.bfl.ai/flux_2/flux2_overview).

```json
{"port_dasha": {"action": "looking straight at the camera, neutral face"},
 "masha_woken_bed": {"modes": ["ref"], "refs": ["results/_Нужные/80_chars2/masha_sleep_bed/masha_sleep_bed__ref_4.png"]}}
```

Новые варианты получают следующие номера, например `ref_5`…`ref_8`. Номер определяет seed, поэтому даже без правки
промпта картинки будут другими. Пока варианты прошлой перегенерации не разобраны, задание повторно не запускается.

## Сцена поиска одной картиной

Сцена собирается так же, как в играх «поиск предметов»: сначала цельная картина, потом каждый предмет рисуется прямо в
ней, а для игры вырезается слоем вместе со своей тенью. Расстановка лежит в `scenes\<сцена>.json` (первая —
`p0_reception`, приёмная клиники).

1. `6_SCENE.bat` — из отобранных фона и мебели собирается эскиз (`results\90_scenes\scene_<сцена>\..._sketch.png`), модель
   перерисовывает его в цельную картину: 4 варианта с LoRA фонов и 4 без неё. В `Otbor.exe` выберите одну картину
   (раздел «Без раздела»).
2. `7_SCENE_ITEMS.bat` — в выбранную картину по одному вписываются открыватели и предметы списка, по 3 варианта
   (`results\91_<сцена>\<предмет>`). Если отобранной картинки предмета нет, на его место ставится серая форма и модель
   рисует предмет по описанию. В `Otbor.exe` выберите по одному варианту каждого предмета: на плитке слой предмета,
   клавиша `A` показывает его в картине.

Повторный запуск делает только недостающие варианты; `scripts\scene.ps1 -Stage items -Only p0rec_key -Force` переделывает
один предмет. Слой предмета — отличия перерисованного куска от картины рядом с местом предмета, положение куска в
картине записано в `meta.json` (`crop`).

## Сборка

`build.bat` собирает `Otbor.exe` компилятором из состава Windows, ничего устанавливать не нужно. Тесты лежат в `tests`.

Разделы, уровни и строки «Куда идёт» лежат в `data/sections.json` и вшиты в программу. После изменения `jobs.json` файл
пересобирается, иначе новые задания попадут в раздел «Без раздела»:

```bat
python tools\build_sections.py jobs.json items_map.json SearchLists.csv data\sections.json
build.bat
```

Скрипт останавливается, если задание не нашло раздел. Комнаты и уровни взяты из `GameDesign.md` §4.2 и §12.1; предмет
попадает в локацию своей первой сцены из `SearchLists.csv`.

## Новая версия

Поменяйте `KitUpdate.Current` в `src/Kit.cs`, соберите `Otbor.exe`, обновите `RELEASE_NOTES.md`, отправьте изменения
в `main`, затем отправьте тег той же версии:

```bat
git tag -a v1.2.1 -m "Otbor 1.2.1"
git push origin v1.2.1
```

GitHub Actions проверит, что версия в программе совпадает с тегом, и создаст релиз с `Otbor.exe` и `UPDATE.bat`.
Новые файлы кита добавляются в `kit/files.txt`.
